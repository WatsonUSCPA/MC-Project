# 在庫係Bot（Slack × AI）

Slack の在庫チャンネルで、作業者（父・母）に「新しい生地の写真を送って」と催促します。届いた写真と情報は、**在庫管理シート（EC サイトが読んでいる「商品データ履歴」）に直接登録**します。
社長（あなた）は同じチャンネルでやりとりを全部見られます。日報や「反応がない」という知らせは、Bot から DM で届きます。

```
#在庫 チャンネル（父・母・社長・在庫係Bot）
  在庫係 → @母 おはようございます！今日入った生地の写真をお願いします📷
  母     → ［写真2枚］全部USA COTTON、200-1052と200-1053
  在庫係 → @母 ✅ 公開しました: USA COTTON 200-1052 1100円 …
  （社長は全部見えている）

社長 ⇄ 在庫係 の DM
  在庫係 → 📋 10/17 の在庫係レポート　父: 登録0件 ⚠️催促2回・反応なし / 母: 登録3件 …
  在庫係 → 🚨 父さんが3日間反応していません
  社長   → 父に今日中に3枚送れって言っといて
  在庫係 → 📣 父さんに伝えました
```

Google Apps Script だけで動くので、サーバーは不要です。

## できること

### 作業者（父・母）とのやりとり — 在庫チャンネル

| 場面 | Bot の動き |
|---|---|
| 毎日 10:00 | 作業者ごとに「今日入った生地の写真を送ってください」と催促します |
| 毎日 17:00 | 今日の登録が0件の人や、登録待ちの写真が残っている人にだけ、もう一度声をかけます |
| 写真が届いたら | 1枚＝1つの生地として受け付けます。商品名と管理番号を聞きます（値段は言われなければ 1100円） |
| 情報がそろったら | 管理番号をチェックし、写真を Cloudinary に上げて、商品データ履歴の4行目に**公開中**で追加します |
| 「200-1051 売り切れ」 | その生地を**非公開**にします |
| 「200-1051 値下げ 800円」 | 値段（D列）を変えます |
| 毎日 14:00 | アップロードから6か月以上たった公開中の生地について「まだ残っていますか？」と聞きます。「ない」なら非公開にします。「ある」なら値下げ候補にして、値段を変えるか聞きます |

前回の登録から日数がたつほど、催促の口調が強くなります（0〜1日: やさしめ / 2〜3日: しっかり / 4日以上: 強め）。

作業者が使うメッセージは次のとおりです。
- 写真を送る（何枚まとめてでも OK）＋「全部 USA COTTON、200-1051〜1053」のように情報を送る
- `200-1051 売り切れ` / `200-1051 値下げ 800円`
- `ある` / `ない` / `ある 800円` … 在庫チェックへの返事
- `状況` / `キャンセル` / `値下げ候補` / `催促オフ` / `催促オン` / `ヘルプ`

### 社長（あなた）向け — Bot との DM

| 場面 | Bot の動き |
|---|---|
| 毎晩 20:00 | **日報**が届きます。作業者ごとの登録件数、登録待ち、「催促したのに反応なし」、公開した生地、止めたミス、売り切れ・値段変更、在庫チェックの結果 |
| 3日間反応がないとき | 「🚨 父さんが3日間反応していません」と知らせます |
| 「報告」と送る | 今の状況をすぐにまとめます |
| 「父に今日中に3枚送ってと伝えて」 | Bot が在庫チャンネルで父に伝えます |
| 「指示: 母にはやさしめに」 | 今後の会話や催促で守るルールを追加します（`指示一覧` / `指示クリア`） |
| 普通に話しかける | 状況をもとに答えます（例:「今週どれくらい登録した？」） |

在庫チャンネルでのあなたの発言には、Bot は反応しません。父・母との会話に割り込まないためです。チャンネルで Bot に指示したいときは `@在庫係` を付けてください。返事は DM に届きます。

### 管理番号のチェック（登録前に自動で行う）

- **同じ管理番号がすでにある** → 登録しません。正しい番号を聞き返します
- **けた数がいつもと違う**（例: `200-762`。いつもは `200-0762` のように4けた）→ 「間違いではありませんか？」と確認します。「OK」と返事があればそのまま登録します
- **ゼロを除くと同じ番号がある**（例: `200-761` と `200-0761`）→ 確認します
- **見たことのないシリーズ番号** → 「新しいシリーズですか？」と確認します
- 全角数字や「ー」などのハイフンは、自動で半角の `-` にそろえます
- Cloudinary の写真のファイル名は、Bot が必ず「日付_管理番号_ランダム」で付けます

## 仕組み：AI はシートにさわらない

```
Slack ──メッセージ・写真──▶ Bot のプログラム（Apps Script）──▶ 在庫管理シート / Cloudinary
                                │        ▲
                     写真と文章  ▼        │ 返事の文章と「どの項目に何を入れるか」だけ
                           AI（OpenRouter 経由の Grok や Claude など）
```

- シートと Cloudinary を読み書きするのは Bot のプログラムだけです。プログラムは、セットアップで「許可」を押したあなたの Google アカウントの権限で動きます
- AI は写真を見て会話するだけです。できる操作は、プログラムに書いたものだけです（行の追加、非公開にする、値段を変える、チャンネルへの伝言、指示の追加）
- AI は設定1行で切り替えられます（スクリプトプロパティ `AI_MODEL`）

## 在庫管理シートとの関係

- 書き込むのは「商品データ履歴」シートだけです。列は増やしません
- 新しい商品は、今までのボタン（DataTransfer）と同じく**4行目**に入り、既存の行は1行ずつ下にずれます
- 書き込む値: A 商品名 / B 管理番号 / C 写真URL（Cloudinary）/ D 値段 / E 空欄 / F `公開中` / G 今日の日付（yyyy/MM/dd）/ H 空欄
- 「入力シート」とボタンは今までどおり使えます
- 会話の状態、在庫チェックの結果、日報用の記録は、シートではなくスクリプトプロパティに保存します

## セットアップ手順

全部で30〜40分くらいです。

### 1. OpenRouter の API キー（済み）

使うモデルは、**画像を読めるもの**にしてください。初期値は `x-ai/grok-4` です。Claude にするなら、OpenRouter のモデル一覧で Claude のモデル名を確認して、`AI_MODEL` に入れてください。

### 2. Cloudinary のキーを確認する

Cloudinary の管理画面（Settings → API Keys）で、**Cloud name / API Key / API Secret** を確認します。チャットなどには貼らないでください。

### 3. Apps Script プロジェクトを作って、ウェブアプリとして公開する

1. [script.google.com](https://script.google.com/) で新しいプロジェクトを作ります（名前の例: 在庫係Bot）。在庫管理シートに付いている Apps Script とは**別の**プロジェクトにします
2. このフォルダの `.gs` ファイルをすべて同じ名前で作り、中身を貼り付けます
3. 「プロジェクトの設定」で「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェックを入れ、`appsscript.json` の中身を貼り付けます
4. 「スクリプト プロパティ」に、まず次の値を入れます

| プロパティ | 値 |
|---|---|
| `AI_API_KEY` | OpenRouter の API キー |
| `AI_MODEL` | （任意）使うモデル。例: `x-ai/grok-4` |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary の Cloud name |
| `CLOUDINARY_API_KEY` | Cloudinary の API Key |
| `CLOUDINARY_API_SECRET` | Cloudinary の API Secret |

5. 右上の「**デプロイ**」→「**新しいデプロイ**」→ 種類で「**ウェブアプリ**」を選びます
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（Slack から呼び出すため。Slack のトークンで確認するので、ほかの人は使えません）
6. 「デプロイ」を押して権限を許可し、表示された**ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピーします

### 4. Slack アプリ「在庫係」を作る

1. [api.slack.com/apps](https://api.slack.com/apps) で「**Create New App**」→「**From a manifest**」を選び、Mcsquareofficials のワークスペースを選びます
2. このフォルダの `slack-manifest.json` の中身を貼り付けます。`request_url` の部分は、手順3でコピーした**ウェブアプリの URL** に書き換えてください
3. 「Create」を押します
4. 「**Install to Workspace**」（または「Install App」）でワークスペースにインストールします
5. 次の2つをコピーします
   - 「OAuth & Permissions」→ **Bot User OAuth Token**（`xoxb-` で始まる）
   - 「Basic Information」→「App Credentials」→ **Verification Token**
6. 「Event Subscriptions」で Request URL の横に **Verified** と出ていれば OK です。出ていなければ「Retry」を押してください

### 5. 在庫チャンネルを用意する

1. Slack で `#在庫` チャンネルを作り、**父・母**を招待します（あなたは作った時点で入っています）
2. チャンネルで `/invite @在庫係` と送って、Bot を招待します
3. **チャンネル ID** を控えます（チャンネル名をクリック → 一番下の `C` で始まる文字列）
4. **あなたのメンバー ID** を控えます（自分のプロフィール → ︙ →「メンバー ID をコピー」。`U` で始まる文字列）
5. 父・母の Slack の**表示名**を「父」「母」などにしてもらうと、日報が読みやすくなります

### 6. 残りの設定と動作確認

1. スクリプト プロパティに、次の値を追加します

| プロパティ | 値 |
|---|---|
| `SLACK_BOT_TOKEN` | Bot User OAuth Token（`xoxb-…`） |
| `SLACK_VERIFICATION_TOKEN` | Verification Token |
| `SLACK_CHANNEL_ID` | 在庫チャンネルの ID（`C…`） |
| `SLACK_ADMIN_IDS` | あなたのメンバー ID（`U…`） |

2. エディタで `setup` を実行します。ログに作業者（父・母）と社長の名前が出れば OK です
3. 動作確認用の関数を実行します
   - `testSlack` … あなたに DM が届くか
   - `testAI` … AI につながるか
   - `testSheet` … シートを読めるか、管理番号チェックの判定はどうなるか（シートは変更しません）
   - `testNag` / `testStockCheck` / `testReport` … 催促・在庫チェック・日報をすぐに1回送ります

### コードを直したとき

Apps Script のコードを変えたら、「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン: 新しいバージョン」→「デプロイ」を押してください。URL は変わりません。

## 設定を変える

`Config.gs` の `CONFIG` で変えられます。

- `DEFAULT_PRICE` … 言われなかったときの値段（50cm 単価）
- `NAG_HOUR` / `FOLLOWUP_HOUR` / `CHECK_HOUR` / `REPORT_HOUR` … 催促・在庫チェック・日報の時刻。変えたら `setup` を実行し直してください
- `NAG_WEEKDAYS` … 催促する曜日（0=日 … 6=土）
- `ESCALATE_DAYS` … 何日反応がなければ社長に知らせるか
- `AGING_MONTHS` / `RECHECK_DAYS` / `CHECKS_PER_DAY` … 何か月たったら聞くか、同じ生地を聞き直す間隔、1人に1日何件聞くか
- `TONE` … Bot の口調

## 制約・注意点

- Slack は3秒以内に返事がないと同じメッセージを送り直してくるので、受け付けたらすぐ返事をして、中身は時間主導トリガーで処理します。**Bot の返事は数十秒〜1分ほど遅れて届きます**（写真には「受け取りました」とすぐ返します）
- 写真と会話の内容は、OpenRouter と、そこで選んだ AI の会社に送信されます
- Slack の無料プランでは、90日より前のメッセージは見られなくなります。在庫の記録はシートに残るので影響はありません
- 受け取った写真は、バックアップとして Google Drive の「在庫係 生地写真」フォルダにも保存します
- 以前の Google Chat 版で作った Google Cloud プロジェクト（Zaiko-bot）は使いません。不要なら削除して構いません
