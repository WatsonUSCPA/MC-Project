# 在庫係Bot（Google Chat × AI）

Google Chat の中で作業者（親）に「新しい生地の写真を送って」と催促し、届いた写真と情報を**在庫管理シート（EC サイトが読んでいる「商品データ履歴」）に直接登録する** Bot です。

今まで手でやっていた次の作業を、Bot が代わりにやります。

1. 写真を Cloudinary にアップロードする
2. 入力シートに書いて、ボタンで商品データ履歴に移す（**公開中**で）

Google Apps Script だけで動くので、サーバーは不要です。

## できること

| 場面 | Bot の動き |
|---|---|
| 毎日 10:00 | 「今日入った生地の写真を送ってください」と催促します |
| 毎日 17:00 | 今日の登録が0件の人や、登録待ちの写真が残っている人にだけ、もう一度声をかけます |
| 写真が届いたら | 1枚＝1つの生地として受け付けます。商品名と管理番号を聞きます（値段は言われなければ 1100円） |
| 情報がそろったら | 管理番号をチェックし、写真を Cloudinary に上げて、商品データ履歴の4行目に**公開中**で追加します |
| 「200-1051 売り切れ」 | その生地を**非公開**にします |
| 「200-1051 値下げ 800円」 | 値段（D列）を変えます |
| 毎日 14:00 | アップロードから6か月以上たった公開中の生地について「まだ残っていますか？」と聞きます（1人1日3件まで、同じ生地は30日おき）。「ない」なら非公開にします。「ある」なら値下げ候補にして、値段を変えるか聞きます |

前回の登録から日数がたつほど、催促の口調が強くなります（0〜1日: やさしめ / 2〜3日: しっかり / 4日以上: 強め）。

### 管理番号のチェック（登録前に自動で行う）

- **同じ管理番号がすでにある** → 登録しません。正しい番号を聞き返します
- **けた数がいつもと違う**（例: `200-762`。いつもは `200-0762` のように4けた）→ 「間違いではありませんか？」と確認します。「OK」と返事があればそのまま登録します
- **ゼロを除くと同じ番号がある**（例: `200-761` と `200-0761`）→ 確認します
- **見たことのないシリーズ番号** → 「新しいシリーズですか？」と確認します
- 全角数字や「ー」などのハイフンは、自動で半角の `-` にそろえます
- Cloudinary の写真のファイル名は、Bot が必ず「日付_管理番号_ランダム」で付けます。写真と番号がずれることはありません

### 作業者が使うメッセージ

- 写真を送る（何枚まとめてでも OK）＋「全部 USA COTTON、200-1051〜1053」のように情報を送る
- `200-1051 売り切れ` … 非公開にする
- `200-1051 値下げ 800円` … 値段を変える
- `ある` / `ない` / `ある 800円` … 在庫チェックへの返事
- `値下げ候補` … 長く残っている生地の一覧
- `状況` … 今日の登録件数と、登録待ちの写真
- `キャンセル` … 登録待ちの写真を全部取り消す
- `催促オフ` / `催促オン` / `ヘルプ`

### 管理者が Bot に指示を出す

- `指示: 今週から値段は1200円がデフォルト` … Bot のふるまいにルールを追加します。全作業者との会話と催促文に反映されます
- `指示一覧` / `指示クリア`
- 指示を出せるのは、スクリプトプロパティ `ADMIN_EMAILS` に入っている人だけです

## 仕組み：AI はシートにさわらない

```
親 ──写真・メッセージ──▶ Bot のプログラム（Apps Script）──▶ 在庫管理シート / Cloudinary
                               │        ▲
                    写真と文章  ▼        │ 返事の文章と「どの項目に何を入れるか」だけ
                          AI（OpenRouter 経由の Grok など）
```

- シートと Cloudinary を読み書きするのは Bot のプログラムだけです。プログラムは、セットアップで「許可」を押したあなたのアカウントの権限で動きます
- AI は写真を見て会話するだけです。シートの鍵は持っていません
- できる操作は、プログラムに書いたものだけです（行の追加、非公開にする、値段を変える）

## 在庫管理シートとの関係

- 書き込むのは「商品データ履歴」シートだけです。列は増やしません
- 新しい商品は、今までのボタン（DataTransfer）と同じく**4行目**に入り、既存の行は1行ずつ下にずれます
- 書き込む値: A 商品名 / B 管理番号 / C 写真URL（Cloudinary）/ D 値段 / E 空欄 / F `公開中` / G 今日の日付（yyyy/MM/dd）/ H 空欄
- 「入力シート」とボタンは今までどおり使えます。手で登録することもできます
- 売れ残りチェックの記録は、シートではなくスクリプトプロパティに保存します

## セットアップ手順

Google Workspace の**管理者権限がなくても**作れます。ただし組織のポリシーで Chat アプリやサービスアカウントキーの作成が禁止されている場合は、管理者に許可を依頼してください。

### 1. Google Cloud プロジェクトを用意する

1. [Google Cloud Console](https://console.cloud.google.com/) で、Workspace のアカウントを使って新しいプロジェクトを作ります
2. 「API とサービス」→「ライブラリ」で **Google Chat API** を有効にします
3. 「OAuth 同意画面」を **内部（Internal）** で作成します
4. 「IAM と管理」→「サービスアカウント」でサービスアカウントを作り、「鍵」→「鍵を追加」→ **JSON** をダウンロードします
   - `iam.disableServiceAccountKeyCreation` のエラーが出る場合は、組織ポリシーでキーの作成が禁止されています。Workspace の管理者に例外を依頼してください
5. プロジェクトの「プロジェクト番号」をメモしておきます

### 2. AI（OpenRouter）の API キーを取得する

1. [openrouter.ai](https://openrouter.ai/) でアカウントを作り、クレジットを入れて API キーを発行します
2. 使うモデルは、**画像を読めるもの**にしてください。初期値は `x-ai/grok-4` です。モデル名は OpenRouter のモデル一覧で確認できます。あとで Claude や Qwen などに変えるときは、スクリプトプロパティ `AI_MODEL` を書き換えるだけです

### 3. Cloudinary の API キーを確認する

Cloudinary の管理画面（Settings → API Keys）で、**Cloud name / API Key / API Secret** を確認します。
これらはチャットなどに貼らず、次の手順のスクリプトプロパティにだけ入れてください。

### 4. Apps Script プロジェクトを作る

1. [script.google.com](https://script.google.com/) で新しいプロジェクトを作ります（名前の例: 在庫係Bot）。在庫管理シートに付いている Apps Script とは**別の**プロジェクトにします
2. このフォルダの `.gs` ファイルをすべて同じ名前で作り、中身を貼り付けます
3. 「プロジェクトの設定」で「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェックを入れ、`appsscript.json` の中身を貼り付けます
   - clasp を使う場合は、このフォルダで `clasp create --type standalone` → `clasp push` でも同じです
4. 「プロジェクトの設定」→「Google Cloud Platform（GCP）プロジェクト」→「プロジェクトを変更」で、手順1のプロジェクト番号を入力します
5. 「スクリプト プロパティ」に次の値を追加します

| プロパティ | 値 |
|---|---|
| `AI_API_KEY` | OpenRouter の API キー |
| `AI_MODEL` | （任意）使うモデル。例: `x-ai/grok-4` |
| `SERVICE_ACCOUNT_KEY` | ダウンロードした JSON ファイルの中身を全部 |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary の Cloud name |
| `CLOUDINARY_API_KEY` | Cloudinary の API Key |
| `CLOUDINARY_API_SECRET` | Cloudinary の API Secret |
| `ADMIN_EMAILS` | 指示を出せる人のメールアドレス（カンマ区切り） |

6. エディタで `setup` を選んで実行し、権限を許可します。ログに在庫管理シートの商品数が表示されます
7. 動作確認用の関数を実行します。いずれもシートは変更しません
   - `testAI` … AI につながるか
   - `testChatAuth` … Chat API の認証が通るか
   - `testSheet` … シートを読めるか、管理番号チェックの判定はどうなるか

### 5. Chat アプリとして登録する

1. Apps Script で「デプロイ」→「デプロイをテスト」を開き、**Head デプロイ ID** をコピーします
2. Cloud Console の「Google Chat API」→「構成」で次のように設定します
   - アプリ名: `在庫係`、アバター URL、説明
   - 「Google Workspace アドオンとして構築」の選択肢が出たら、**オフ**にします（この Bot は従来型の Chat アプリとして作っています）
   - 機能: 「1:1 のメッセージを受信する」をオンにします
   - 接続設定: **Apps Script プロジェクト**を選び、デプロイ ID を貼り付けます
   - 公開設定: 自分と作業者のメールアドレスを指定します
3. 保存します

### 6. 使い始める

1. 作業者が Google Chat で「＋ 新しいチャット」→「アプリを検索」から `在庫係` を探し、1対1のチャットを始めます
   - チャットを始めた人が、催促の対象として自動で登録されます（`showSpaces` で確認できます）
2. `testNag` を実行すると催促が、`testStockCheck` を実行すると在庫チェックが、すぐに1回届きます

## 設定を変える

`Config.gs` の `CONFIG` で変えられます。

- `DEFAULT_PRICE` … 言われなかったときの値段（50cm 単価）
- `NAG_HOUR` / `FOLLOWUP_HOUR` / `CHECK_HOUR` … 催促と在庫チェックの時刻。変えたら `setup` を実行し直してください
- `NAG_WEEKDAYS` … 催促する曜日（0=日 … 6=土）
- `AGING_MONTHS` / `RECHECK_DAYS` / `CHECKS_PER_DAY` … 何か月たったら聞くか、同じ生地を聞き直す間隔、1人に1日何件聞くか
- `TONE` … Bot の口調

## 制約・注意点

- Chat は30秒以内に返事がないとエラー表示になります。そのため写真の受け付けとシートへの登録は、時間主導トリガーで非同期に処理します。結果は数十秒〜1分ほどで届きます
- テキストだけのメッセージは、その場で AI に問い合わせて返事します。応答が遅いモデルだと30秒を超えることがあるので、速いモデルを選んでください
- 写真と会話の内容は、OpenRouter と、そこで選んだ AI の会社に送信されます
- HEIC など JPEG/PNG 以外の写真は、AI には Drive のサムネイルを見せます。Cloudinary からは JPEG として配信します
- 受け取った写真は、バックアップとして Drive の「在庫係 生地写真」フォルダにも保存します
